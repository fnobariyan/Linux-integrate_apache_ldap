# LDAP + Apache Authentication Lab

A hands-on lab demonstrating how to configure an OpenLDAP directory on Ubuntu Server and use it to authenticate users accessing an Apache website on Rocky Linux.

## Lab Environment

| Component        | Details              |
| ---------------- | -------------------- |
| LDAP Server OS   | Ubuntu Server        |
| Apache Server OS | Rocky Linux          |
| LDAP Domain      | `mcloud.local`       |
| Base DN          | `dc=mcloud,dc=local` |
| LDAP Server IP   | `192.168.56.109`     |
| Apache Server IP | `192.168.56.111`     |
| LDAP Port        | `389`                |
| HTTP Port        | `80`                 |
| LDAP User        | `fatemeh`            |
| LDAP Group       | `devops`             |

## 1. Install and Configure OpenLDAP

Run these commands on the Ubuntu LDAP server.

### Install OpenLDAP

```bash
sudo apt update
sudo apt install slapd ldap-utils -y
sudo systemctl enable --now slapd
sudo systemctl status slapd
```

### Check LDAP Port

```bash
sudo ss -lntp | grep 389
```

### Verify LDAP Base DN

```bash
ldapsearch -x -H ldap://localhost -b "dc=mcloud,dc=local"
```

### Check LDAP Administrator DN

```bash
sudo ldapsearch -Y EXTERNAL -H ldapi:/// -b "cn=config" "(olcRootDN=*)" olcRootDN
```

### Test LDAP Administrator Authentication

```bash
ldapwhoami -x -H ldap://localhost -D "cn=admin,dc=mcloud,dc=local" -W
```

## 2. Create Organizational Units

Create the file `/etc/ldap/base-groups.ldif`:

```ldif
dn: ou=people,dc=mcloud,dc=local
objectClass: organizationalUnit
ou: people

dn: ou=groups,dc=mcloud,dc=local
objectClass: organizationalUnit
ou: groups
```

Add the organizational units:

```bash
ldapadd -x -H ldap://localhost -D "cn=admin,dc=mcloud,dc=local" -W -f /etc/ldap/base-groups.ldif
```

## 3. Create the devops Group

Create `/etc/ldap/group.ldif`:

```ldif
dn: cn=devops,ou=groups,dc=mcloud,dc=local
objectClass: posixGroup
cn: devops
gidNumber: 5000
```

Add the group:

```bash
ldapadd -x -H ldap://localhost -D "cn=admin,dc=mcloud,dc=local" -W -f /etc/ldap/group.ldif
```

## 4. Create an LDAP User

Generate a password hash:

```bash
slappasswd
```

Create `/etc/ldap/user.ldif`:

```ldif
dn: uid=fatemeh,ou=people,dc=mcloud,dc=local
objectClass: inetOrgPerson
objectClass: posixAccount
objectClass: shadowAccount
uid: fatemeh
sn: nobariyan
givenName: fatemeh
cn: fatemeh nobariyan
displayName: fatemeh nobariyan
uidNumber: 7000
gidNumber: 5000
userPassword: {SSHA}<HASH>
gecos: fatemeh nobariyan
loginShell: /bin/bash
homeDirectory: /home/fatemeh
```

Replace `{SSHA}<HASH>` with the hash generated by `slappasswd`.

Add the user:

```bash
ldapadd -x -H ldap://localhost -D "cn=admin,dc=mcloud,dc=local" -W -f /etc/ldap/user.ldif
```

## 5. Verify LDAP Entries

### Check the Base DN

```bash
ldapsearch -x -H ldap://localhost -LLL -b "dc=mcloud,dc=local" -s base
```

### Check the Group

```bash
ldapsearch -x -H ldap://localhost -LLL -b "cn=devops,ou=groups,dc=mcloud,dc=local"
```

### Check the User

```bash
ldapsearch -x -H ldap://localhost -LLL -b "uid=fatemeh,ou=people,dc=mcloud,dc=local"
```

### Optional: Add the User to the Group

Create `/etc/ldap/add-member.ldif`:

```ldif
dn: cn=devops,ou=groups,dc=mcloud,dc=local
changetype: modify
add: memberUid
memberUid: fatemeh
```

Apply this only if the membership has not already been added:

```bash
ldapmodify -x -H ldap://localhost -D "cn=admin,dc=mcloud,dc=local" -W -f /etc/ldap/add-member.ldif
```

## 6. Install Apache on Rocky Linux

Run these commands on the Apache server.

```bash
sudo dnf install httpd openldap-clients nmap-ncat -y
sudo systemctl enable --now httpd
```

Check the LDAP authentication modules:

```bash
httpd -M | grep ldap
```

The expected modules are `ldap_module` and `authnz_ldap_module`.

## 7. Configure LDAP Name Resolution

Edit `/etc/hosts`:

```bash
sudo vi /etc/hosts
```

Add the LDAP server entry:

```text
192.168.56.109 ldap.mcloud.local
```

Verify name resolution:

```bash
getent hosts ldap.mcloud.local
```

Test connectivity to the LDAP port:

```bash
nc -zv ldap.mcloud.local 389
```

## 8. Create a Test Website

Create the website directory:

```bash
sudo mkdir -p /var/www/html/dl-mcloud-local
```

Create a test page:

```bash
echo "LDAP Apache Test" | sudo tee /var/www/html/dl-mcloud-local/index.html
```

## 9. Configure Apache LDAP Authentication

Create the configuration file:

```bash
sudo vi /etc/httpd/conf.d/ldap.conf
```

Add the following configuration:

```apache
<VirtualHost 192.168.56.111:80>

    DocumentRoot "/var/www/html/dl-mcloud-local"

    <Directory "/var/www/html/dl-mcloud-local">
        Options -Indexes +FollowSymLinks
        AllowOverride None

        AuthType Basic
        AuthName "LDAP Authentication"
        AuthBasicProvider ldap

        AuthLDAPURL "ldap://ldap.mcloud.local:389/dc=mcloud,dc=local?uid?sub?(objectClass=person)"

        AuthLDAPBindDN "cn=admin,dc=mcloud,dc=local"
        AuthLDAPBindPassword "REPLACE_WITH_ADMIN_PASSWORD"

        Require valid-user
    </Directory>

    ErrorLog /var/log/httpd/dl-mcloud-local_error.log
    CustomLog /var/log/httpd/dl-mcloud-local_access.log combined

</VirtualHost>
```

Replace `REPLACE_WITH_ADMIN_PASSWORD` with the actual LDAP administrator password on the server. Do not publish the real password in a public repository.

## 10. Validate and Reload Apache

Check the configuration syntax:

```bash
sudo apachectl -t
```

Expected output:

```text
Syntax OK
```

List configured virtual hosts:

```bash
sudo httpd -S
```

Reload Apache:

```bash
sudo systemctl reload httpd
```

Check the service status:

```bash
sudo systemctl status httpd
```

## 11. Test LDAP Authentication

Open the website in a browser:

```text
http://192.168.56.111
```

Enter the LDAP credentials:

* Username: `fatemeh`
* Password: The password assigned to the LDAP user

After successful authentication, the browser should display:

```text
LDAP Apache Test
```

Alternatively, test authentication from the Apache server:

```bash
curl -I -u fatemeh http://192.168.56.111
```

The command prompts for the user's password. A successful request should normally return:

```text
HTTP/1.1 200 OK
```

## Security Notes

* Never publish real passwords, password hashes, or secret configuration files.
* Plain LDAP over `ldap://` is suitable only for an isolated lab network. Use TLS/LDAPS or StartTLS and secure credential handling in production.
* Protect HTTP Basic Authentication with HTTPS outside an isolated test environment.
* Run `ldapadd` only when the entries do not already exist. Use `ldapmodify` to update existing entries.
